Columns, statuses, identities

Copies = SINEderella copies of that label per genome. Loci = rows of the orth table: C flank-mapped, M rescued with both flanks, N from nested loci. Shared (SINE) = copy in both genomes; rsi only (PM) = R. sinicus only; rfe only (MP) = R. ferrumequinum only; shared % = shared / loci. Identities (%) are ComPair's, median and 10–90 % range: copy vs its reference consensus (divergence = 100 − identity), copy vs copy at shared loci, left flanks. E1–E4, HE1 are the elements of nested loci (sine_nest naming), without identities. The links open the SINE loci browser on that subfamily's alignments of that status (data/by_reference/ from orth_split.py; nested-locus rows and superseded flank rows have no alignment there); inside it the subfamily list, the SINE / PM / MP / rejected chips and the name box narrow further, or open all 53,163 alignments at once (30 MB).

Main flank-mapping rows only (clusters C…); rescue (M) and nested (N) rows are left out, so a locus a run holds as an M row counts as missing from that run. Check: each input copy ±10 kb was aligned to the other genome (minimap2 -x asm20) and its junction lifted; agree = the row's partner is within 50 bp of the lifted junction. Disagree is not the same as wrong: at segmental duplications the check itself can pick the wrong copy. Before the junction fix (SINE_orth_loc 41ccc90) about 5 % of anchors lay more than 50 bp off the window junction, because a reference longer than its copy (partial copy, composite) can start anywhere in the left flank; the comparison then uses the window position. With the fix the junction is the annotated copy's own start: 1.6 % remain off, and 198 more rows become testable.
